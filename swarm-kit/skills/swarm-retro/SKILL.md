# Swarm Retro（复盘自优化）

把 GPTSwarm 的图优化落成两条腿：**节点优化**（改各兵种提示词）与**边优化**（改编排路由规则）。蜂群用得越多，应该变得越准。

## 流程

1. **取证**：读 `.swarm/<mission-id>/STATUS.md` 与全部任务卡、回执；必要时查会话中派发与汇总的原文。
2. **归因**：把问题归到一类（多于两类就分多次复盘）：

   | 症状 | 归因 | 优化对象 |
   |---|---|---|
   | 侦察漏报（该找到的没找到） | scout 能力不足 | `agents/scout.md`（节点） |
   | 工蜂越权或烂尾 | 提示词弱，或任务卡所有权划得不准 | `agents/worker.md`（节点）或卡模板（边） |
   | 验收放水/误判 | judge 纪律不足 | `agents/judge.md`（节点） |
   | 分解不当（卡不独立、粒度失衡） | 分解规则缺失 | `swarm-lead` 分解规则（边） |
   | 派发上下文不足 | 派发模板缺字段 | `swarm-lead` 派发步骤（边） |
   | 不该组群而组群（或反之） | 分级阈值不准 | `swarm-lead` L1–L4 表（边） |

3. **提议**：每个失败模式给出**一个最小修改**（diff 形式），标明改哪个文件、为什么、预期下次如何生效。节点与边各至多一条。
4. **确认后落地**：经用户同意才修改本插件目录下的文件；修改后走插件重载流程生效。**一次复盘最多落地两条修改**——改多了无法归因。

## 输出

复盘报告：损失（token/时间）→ 失真环节 → 修改建议（diff）→ 是否已落地。
