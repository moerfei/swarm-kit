# Swarm Lead（蜂群编排手册）

你是编排者（主会话本身）。本手册把多代理蜂群研究（理论出处见 `references/patterns.md`）落成纪律：何时组群、怎么建巢、怎么派发、怎么收网。

## 1. 何时组群——L1–L4 努力分级

先分级，再决定动不动用蜂群。**L1 永远不组群**——编排本身有开销（分解与汇总的额外调用），低价值任务组群是净亏损。

| 级别 | 任务特征 | 蜂群形态 |
|---|---|---|
| L1 | 单点查改、答案明确、一个文件内 | 不组群，自己完成 |
| L2 | ≥3 个互不依赖的实现子任务 | 2–3 只工蜂并行，各卡所有权隔离 |
| L3 | 广度优先：调研、选型、排查、多方案 | 3–5 只侦察蜂 fan-out，编排者汇总 |
| L4 | 高风险交付：发布、迁移、不可逆变更 | 工蜂施工 → 2–3 只评审蜂独立投票，多数通过才收网 |

预算红线：蜂群约消耗单代理 **10–15×** 的 token（Anthropic 多代理研究系统实测 15×）。任务价值撑不起这个乘数时，降级处理或放弃组群。

## 2. 建巢——蜂巢黑板协议

所有共享状态落在 `.swarm/<mission-id>/`（mission-id 用 `YYYYMMDD-短slug`，如 `20260916-orm选型`）：

```
.swarm/<mission-id>/
├── mission.md              # 目标 / 约束 / 成功标准 / 预算（编排者写一次）
├── STATUS.md               # 看板：每行一张卡 | 兵种 | planned·dispatched·done·blocked | 一句话（Jev 分流记 done(auto-pass,jev) / rework(auto-fail,jev)）
├── tasks/T01-<slug>.md     # 任务卡
├── results/T01.md          # 回执（由该卡的代理写）
└── decisions.jsonl         # Jev 预审日志（可选，scripts/jev.sh 追加）
```

任务卡必含四要素：

1. **范围**——做什么，明确不做什么。
2. **文件所有权**——该代理唯一可写的文件清单（写者唯一，从制度上消除并行写冲突）。
3. **完成标准**——逐条可验收（评审蜂要照着判）。验证必须到**运行时**（跑起来看行为），不止构建通过；一张卡同时生产共享契约的两端（生产者+校验者）时，必须用自家真实产物互测，自造测试件只能作补充、不能替代，也不得以"对端未就绪"豁免。
4. **交付路径**——产物放哪、回执写到哪。

协作纪律（A2A 式不透明协作）：代理之间只经黑板交换信息，互不读对方内部过程；**编排者是唯一通读全部回执并做汇总的角色**。

## 3. 派发与收网

1. **分解**：拆成 2–5 张真正独立的任务卡。拆不出独立性就不要硬拆——回炉自己干。
2. **建巢**：写 `mission.md`、任务卡、`STATUS.md`。
3. **派发**：在**同一条消息里并行发起所有 Agent 调用**（并发执行）；长任务加 `run_in_background: true`。派发 prompt 必须自包含——代理看不到你的会话，只需给出任务卡路径 + 黑板路径。
4. **跟进**：后台代理完成会收到通知；某只蜂卡住或答非所问时，用 `SendMessage` 定向追问或 resume 它（这是对 handoff 的近似，控制权仍在编排者手里）。
5. **预审分流**（可选，默认影子模式）：派 judge 前对每份回执跑一次 Jev 决策调用——全部完成标准 p≥0.97 → auto-pass 免派 judge；任一 p≤0.30 → auto-fail 退回工蜂；灰区照常派 judge。**L4 永不 auto-pass**；调用失败当作未预审。协议、阈值与启用条件见 `references/jev.md`。
6. **汇总**：由编排者**综合**回执（结论优先、证据随后），不是罗列回执。结论互相矛盾时加派评审蜂投票，不自行裁断。
7. **收尾**：更新 `STATUS.md` 全部为 done/blocked；向用户报告结论 + 证据路径；蜂巢目录保留还是删除，问用户。

## 4. 兵种

- `scout`（只读）：调研、定位、取证、对比
- `worker`（可写）：按所有权清单施工
- `judge`（只读）：验收、投票；L4 交付前必派

## 5. 失败预案

- 回执为空/超时 → `SendMessage` resume 一次；再失败，该卡收回归编排者自己做，STATUS 标注。
- 两只工蜂改了同一文件 → 所有权协议被违反：停群，按回执时间戳判定保留方，重派一张验证卡。
- 质量存疑 → 加派 1–2 只 judge 复核，多数裁决。
- Jev 预审调用失败/超时 → 静默降级为"未预审"，照常派 judge，最多重试一次——预审是纯优化，不是正确性依赖。

## 6. 复盘

任务结束后建议用户运行蜂群复盘（`swarm-retro` 技能）：把这次暴露的失败模式变成对蜂群自身的最小修改——蜂群用得越多次应该变得越准。
